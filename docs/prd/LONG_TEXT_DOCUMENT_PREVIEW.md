## 产品目标与核心任务

SenseFlow 的核心体验是“找回一段复制过的长文本，划过去即能完整阅读，需要时直接修改再使用”。长文编辑是本次重构主线；OCR 闪退作为先行稳定性阻塞处理，其余工具、目录清理与 RAG 为后续工作。

目标用户任务：浏览历史 → 停在目标长文 → 上方中央悬浮预览阅读全文 → 点击正文修改 → 保存为新记录或复制结果。正文支持选取、撤销、输入中文与内部滚动。

根据用户最终澄清，“类似 Word”仅指宽松阅读与直接编辑；不提供标题栏、红绿灯、查找、字号或文档工具栏。首版编辑纯文本（含原样 Markdown/代码），不承诺 .docx、分页打印、富文本字体样式或 Word 文件兼容；这些是另立需求的扩展，不能把假富文本按钮放进界面。

## 首版范围与默认决策

- 鼠标悬停长文卡片是主要入口；Space/预览按钮提供键盘与无 hover 的替代入口。
- 悬停查看不抢键盘焦点、不写剪贴板、不调用 AI、不保存新历史。
- 点击正文进入编辑，并把同一张展开卡片固定；编辑期间 hover 别的卡片不替换正文。
- 原始捕获文本保持不变；编辑自动保存独立草稿，“保存为新记录”产生明确的新版本；本轮不提供覆盖原记录。
- 复制全文取当前文档，Cmd+C 取当前选区；保存、复制与粘贴是不同动作。
- 默认一份可编辑文档会话。自动预览在既有历史窗口内展开，不创建文档窗口；其他文档请求在编辑会话结束前不替换它。
- 首版默认纯文本，不自动更换引号、破折号、大小写或原有换行。

这些是本次为保证可实施性确定的产品默认，不假称已经用户逐项确认。变更须同步 PRD 和设计。

## 场景与触发

| 场景 | 用户行为 | 系统结果 |
|---|---|---|
| 快速扫过多张卡片 | 连续移动鼠标 | 不逐项弹窗、不开全文读任务 |
| 阅读长文 | 在被截断文本卡片停留 | 约 350 ms 后出现文档预览，展示完整内容 |
| 移入预览 | 从卡片经过间隙进入窗口 | 预览保持，可滚动和选取 |

| 划过其他卡片 | 文档处于编辑会话 | 当前文档不变，不弹确认，不丢草稿 |
| 保存版本 | 点击“保存为新记录”/Cmd+S | 当前完整文本保存成新历史版本，原始记录保留 |

## 如何判定需要展开

卡片按实际内容是否超出摘要显示区域判定，而非简单“超过 N 字”。摘要排版溢出、较多换行或长单行截断都显示轻量“全文”入口。卡片只使用捕获/摘要阶段生成的有限采样信息；禁止为所有历史记录全文排版。显式预览对任意文本可用，避免判定误差阻止查看。

短文本可以有小型内容适配预览；长文使用大文档阅读区。绝不以省略号/固定 8 行作为完整文档。

## 悬停与窗口规则

1. 进入卡片启动候选延迟；离开、横向滚动、搜索结果变化、隐藏历史取消候选。只允许最后一个有效候选打开。
2. 自动预览显示后，展开卡片的实际屏幕矩形构成保持区域；展开动画过程中不检查离开，鼠标移入正文不能触发关闭。
3. 离开保持区域超过容忍期，且未选取/拖动/固定，自动预览关闭；按下鼠标拖选期间不执行 hover close。
4. 点击正文进入固定编辑会话。鼠标离开或应用失去焦点不丢编辑内容；关闭按钮走草稿关闭流程。
5. 用户关闭自动预览后，鼠标不离开原卡片再进入就不立即重开。编辑窗口未关闭时，其他 hover 不更换文档。
6. 指针预览不自动 makeKey，不抢原应用/搜索框输入；编辑明确获得焦点。阅读与编辑共用原历史窗口，内部焦点转移不得触发历史误隐藏。
7. 原卡片在队列内展开，底边固定、窗口向上提供空间；后续卡片向右让出位置，超出横向视口可滚动。
8. 编辑会话固定在所属历史窗口；编辑期间不切换 A/B 窗口。外接屏断开处理需保持编辑缓冲区和光标，真实多屏验收待完成。

## 展开卡片布局

展开卡片采用原生玻璃，顶部仅显示来源与关闭。正文透明，约15pt系统字体与宽松边距；完整原文可以选择和垂直滚动，点击直接编辑。编辑时显示必要的复制、保存与草稿状态，不提供文档工具栏。

高度按有限内容排版计算：最小240pt，最大620pt且服从当前屏幕可用空间；超出内部滚动。图片按比例适配。同排底边固定，后续卡片按真实宽度变化向右让出位置。编辑时不随每次输入改变尺寸，避免光标跳动。

## 编辑能力与数据语义

- 标准输入、选区、复制/剪切/粘贴、撤销/重做；中文输入法 marked text 未提交时，禁止保存版本/执行工具/切换文档的内容覆盖。
- 支持 emoji、组合字符、混合换行和空行。显示层不能把 NSRange 的 UTF-16 坐标直接当 Swift Character offset。
- 窗口加载只读原文，进入编辑才建立草稿；原文保存快照与当前草稿明确区分。
- 本地草稿约 1 秒 idle checkpoint，最迟 5 秒一个 durable checkpoint（大型文本需按预算校准）；写入失败保持内存并提示“草稿未保存”。只有持久化成功才能显示“草稿已保存”。
- Cmd+S 保存为新记录，并更新当前会话的基准版本；后续修改仍归同一编辑会话。没变化时不新增重复历史；文本与既有记录相同则返回该已有记录并更新 recency，不复制一份假版本。
- 空文稿可作为草稿，保存为历史时说明空内容不符合历史捕获规则，不默默清空原记录。
- 新版本保留来源关联与实际保存时间；之后复制相同内容复用稳定 ID，不删除重建。
- 放弃当前编辑会话删除其草稿；对话框中的“放弃”不删除原记录或其他已保存版本。
- 点击外部应用不弹打断性的未保存提示，固定窗口保持；明确关闭才处理未归档修改。
- 原记录被历史清理/用户删除时，已打开的内容仍可保存新记录；有草稿的清理关系明确，清空全部历史会提示草稿并一并按用户选择清理，不能隐藏保留敏感副本。

## 退出与恢复

已提交草稿恢复属于数据恢复，不依赖崩溃后弹窗。崩溃/强制退出可能损失最后一次 durable checkpoint 之后的输入，界面不能承诺零丢失。下次开启存在草稿的记录时提供“继续草稿/查看原文/删除草稿”，不在启动时自动显示敏感全文。

正常 Cmd+Q/关闭有 dirty 会话时，提供保存版本、保留草稿并退出、取消；保留草稿需落盘成功才能正常关闭。强制退出不可拦截，仍依靠上次 checkpoint。

## 性能与隐私

- 打开/编辑完全本地工作，无 API key、无联网也可用。单次 hover 不触发 OCR、embedding、屏幕截图或 AX 树遍历。
- 不在 hover timer、SwiftUI body 或每个按键回调中读数据库/磁盘、hash 全文、转换全文 attributed string 或重建 text storage。
- 只加载当前有效文档；旧请求结果丢弃且不创建窗口。100k 字符必须完整可编辑；1M 字符作为压力验收，无静默截断，显示加载状态并允许取消。
- 原生滚动使用按 viewport 的布局；超过窗高后滚动，不先把全文布局完再打开。
- 本机 100k fixture 拟定：hover 延迟后的首屏 p95 ≤150 ms（不含 350 ms 停留等待），编辑按键到显示 p95 ≤50 ms；同机 Release 测量，不宣称已达标。记录峰值 RSS 与每次 hover 任务数。
- 草稿受相同隐私过滤/清理政策约束，不写原文到日志，不自动上传恢复文本。

## 2026-10-06：用户体验修订（优先于此前窗口样式）

历史方案（已被下方最终动效澄清替代）：hover 后移到中央。不能出现系统标题栏或红绿灯，也不能先弹出普通窗口。卡片、搜索/历史、文档与操作按钮统一采用 macOS 26+ 原生 SwiftUI Liquid Glass；当前用户设备 macOS 27 使用该路径。旧系统保留单一原生 material 降级。长文正文背景透明，不能以不透明灰色/白色盖住玻璃。

非目标：重建编辑缓冲区、引入 HTML 编辑器、用截图代替可编辑正文。保留原文、草稿、撤销和IME合同。

实现边界：AppKit 只承担透明浮层承载、焦点和窗口几何；SwiftUI 绘制玻璃/自定义关闭与拖动区。展开约380ms；Reduce Motion 时立即定位并短淡入。正文在最终固定尺寸完成加载，展开期间只显示玻璃轮廓，之后渐显工具/全文，避免每一帧重新排版长文。手动按钮/Space预览固定浮层，纯hover保留离开容忍期。

完成条件：源卡片有正确屏幕坐标；向屏幕中心展开，无遮蔽系统红绿灯；正文/卡片使用原生glassEffect而非灰色material叠层；编辑/关闭/拖动正常。验证：最小构建、隔离AppKit正文安全验证及实际动效体验；不把构建成功称为动画丝滑或性能预算验收。

补充：图片采用同一玻璃浮层/展开动画，按原图比例适配，保留原图，展示按需解码预览。浮层只以预览和点击正文编辑为主，删除查找、字号、等宽字体与文档工具栏；仅保留来源/关闭及编辑保存、复制动作。普通鼠标垂直滚轮在历史横向列表转换为左右滚动；触控板已有横向滚动不拦截，正文垂直滚动不受影响。玻璃使用 appearsActive 偏好保持外观，不通过抢焦点实现。
