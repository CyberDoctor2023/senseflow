# 历史滚轮恢复

目标：历史卡片与卡片间隙的普通鼠标竖向滚轮转为横向滚动；触控板精度、阶段、惯性和原生边缘回弹保留。预览正文保持原生纵向滚动。

诊断：现有验证只向 NSScrollView 直接传入事件，没有验证历史区域的本地事件监视器命中路径。本轮补查生产布局区域和实际事件转发，避免仅修改曲线。

完成条件：真实历史视口收到普通滚轮后产生有效位移；不命中历史视口的事件原样返回；预览正文不受影响。只补充这一回归风险，不增加常量或 Mock 性能测试。

验证：既有隔离文档工作流中的原生滚轮与正文滚动验证、focused build；物理设备手感由实际体验验收，不将合成事件视为物理输入测量。

实现：滚轮专用原生 overlay，仅轮事件命中；点击与拖动穿透。删除全窗口 monitor，并移除事件携带窗口身份的依赖。生产响应器转发验证72pt，完整隔离文档流程通过；物理输入仍待体验。

## 实机仍失效后的修正

用户确认预览正文正常，历史列表仍不响应。上轮直接调用 WheelView 不能证明 SwiftUI 命中会把物理滚轮交给 overlay。删除依赖 currentEvent 的 overlay 命中方案，改由历史 NSPanel.sendEvent 接收滚轮并按列表区域路由；面板仅持有弱路由对象。其他事件走原生窗口分发，预览独立窗口不接入此路由。验证提升为真正调用历史面板 sendEvent 的输入路径，而非直接调用滚轮处理函数。

## 恢复可用版本的位移方式

用户再次报告失效。对比 out/2026-10-07-native-history-scroll/ClipboardListView.before.swift 与当前实现：此前普通鼠标竖向滚轮直接计算 clipView 横向位置，之后改为重写 CGEvent 轴并调用 NSScrollView.scrollWheel。隔离原生合成行事件通过并不能证明实际设备事件被该控件接受。

恢复已存在的直接 clipView 位移：滚轮行单位24pt、精确输入使用像素值，按文档/视口可滚范围限制。原生横向输入保持事件原样转发。历史窗口入口路由保留，预览正文不修改。本轮优先恢复基础移动；竖向鼠标转横向的边缘回弹不以另一套自定义曲线替代，不宣称与触控板回弹完全相同。

## 2026-10-08 边缘回弹时鼠标滚轮反向
用户复现：普通鼠标到边缘回弹尚未完成时，立刻反向滚动变慢；触控板正常。当前适配把120ms内的普通滚轮统归同一changed手势，没有方向切换边界。假设：反向仍被旧弹性手势阻力吸收。
目标：普通鼠标反向时取消上一段适配手势并以began提交当前反向增量；零增量不改变方向，仍保留原生NSScrollView弹性/回弹。真实触控板phase/momentum保持原转发，不更改滚动倍率/曲线。先验证原生事件序列与实际AppKit位移；合成事件不能替代物理设备主观验收。完成条件包含两边回弹反向、快速交替、同向连滚、触控板与正文回归；验证不足明确记录。

原生实测补充：仅cancelled+began不足，右边缘仍在超界1732.5→1729（50ms，仅3.5pt），旧弹性位移仍吃掉输入。因此只在反向且clip真实越界时，使用公开弹性开关和constrainBoundsRect/scroll(to:)结束旧超界位移，再恢复原生弹性并提交新反向手势；不在正常区间改动位置，不持续关闭回弹。不宣称该交接与Apple私有物理曲线完全一致。
